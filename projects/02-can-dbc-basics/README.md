## CAN报文和DBC有什么区别？

| 对象 | 作用 | 本例 |
| --- | --- | --- |
| CAN报文 | 总线上传输的数据，包含标识符、长度、数据等信息 | 标准帧ID 0x321，DLC=1，DATA=01 |
| DBC文件 | 描述如何把数据位解释为信号的离线说明文件 | 第0字节为ReadySt，1表示已就绪 |

DBC本身不会发送报文，也不是采集日志。没有对应定义，不能仅凭01就判断真实车辆状态。

## 最小定义

标准CAN数据帧；ID为0x321（十进制801），DLC为1。ReadySt占起始位0起的8位，Intel字节序，无符号，比例1、偏移0；0=未就绪，1=已就绪。其他编码未定义，不应直接当成已就绪。

## 如何开始

1. 打开CSV，先确认ID、DLC和DATA；所有DATA均以十六进制表示。
2. 打开DBC，对照BO_（报文）、SG_（信号）、VAL_（文字映射）。
3. 完成[练习](practice.md)，先自己判断，再查看参考答案。无需编程或连接硬件。

预期：00 → ReadySt=0（未就绪）；01 → ReadySt=1（已就绪）。
