# 详细练习

## 1. 打开整理前反例

打开examples/before_ambiguous.csv。只看LampReq/FanReq一行：起始位0、长度2，备注却分别说bit0、bit1可以独立开关。

问题不在于2位信号一定错误，而在于本例的含义是两个独立请求，表格却没有分别给出信号行。该反例不是“语法坏文件”，不应直接拿去生成DBC。

## 2. 对照整理后的表格

打开examples/after_matrix.csv。应有三行信号，LampReq、FanReq、DemoCount各一行。

逐行检查：ID都是0x456、长度都是3、帧类型都是standard；起始位分别为0、1、8，位长分别为1、1、16。信号占用位为{0}、{1}、{8至23}，没有重叠，也没有超出3字节的24位范围。位2至7未使用。

注意：同一ID出现在三行是正常的；三个信号共享一条报文定义。

## 3. 查看DBC

打开examples/demo_signal_boundaries.dbc。找到BO_ 1110 DemoPacked: 3 TeachSender：1110就是0x456的十进制写法。

下面应有三条SG_。0|1、1|1和8|16分别对应表格的起始位和位长；@1+表示Intel、无符号；(1,0)表示比例1、偏移0。VAL_只为两个请求定义0/1文字映射。

## 4. 手工计算A行

打开sample_frames.csv，暂时遮住expected列。A行为03 34 12。

1. 第0字节03=二进制00000011。从右边起第1位是bit0、第2位是bit1；两位都是1。
2. LampReq=1、FanReq=1。
3. 后两字节按低字节在前组合：0x34+256×0x12=52+256×18=4660。
4. 比例1、偏移0，DemoCount仍为4660。
5. 与CSV预期列核对。

## 5. 改一处，观察哪些值会变

B行02 34 12：只改第0字节。02=00000010，因此LampReq=0、FanReq=1，DemoCount仍为4660。

C行01 01 00：LampReq=1、FanReq=0；DemoCount=0x0001=1。注意01 00的计数值在本例不是256。

## 6. 常见错误

| 错误 | 原因或修正 |
| --- | --- |
| 看到2位就必须拆 | 如果编码本来是一个枚举，应保留；本例因两个请求独立才拆 |
| 高低字节永远拆 | 本例是同一个16位计数值，应保留为一个数值 |
| 所有ID行都去重 | 会丢掉同一报文下的其他信号，应区分报文表与信号表 |
| 34 12算成0x3412 | 本例Intel定义是低字节34在前，结果0x1234 |
| 请求开启就是设备已运行 | 本例没有实际反馈信号，不能作此判断 |
| CSV能被所有工具直接导入 | 不同工具和转换器的列名、编码、输入格式不同，须先确认 |
