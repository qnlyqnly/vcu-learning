# 01 · Excel 转 DBC 入门实验

**面向汽车电子初学者，先跑通一份自己的模拟 CAN 通信矩阵。**

## 这个项目能做什么？

- 用 Excel 的 `Messages`、`Signals` 两张表定义 CAN 报文和信号；
- 用 Python 3（无需安装第三方库）批量生成经典 CAN 的 `.dbc` 文件；
- 支持 11 位标准帧 / 29 位扩展帧，Intel（小端）、有符号及无符号整型；
- 对非法 ID、越界或重叠信号、错误字节序等情况报错；
- 附带 **2 条独立模拟报文、7 个模拟信号、8 项基础测试**。

这是练习工具，不是企业生产用的 DBC 转换器。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `标准通信矩阵模板.xlsx` | 说明页及 Messages / Signals 两张数据表 |
| `excel_to_dbc.py` | 转换器核心程序 |
| `一键转换_Windows.bat` | Windows 双击执行入口 |
| `演示生成.dbc` | 脚本用模板生成的结果 |
| `test_converter.py` | 8 项基础单元测试 |

## 先跑起来（Windows）

1. 安装 Python 3，命令行运行 `python --version` 或 `py -3 --version`。
2. 打开 `标准通信矩阵模板.xlsx`，先查看 `Messages` 和 `Signals`，不要急着修改，保存并关闭。
3. 把 Excel 和所有脚本放在同一文件夹，**双击 `一键转换_Windows.bat`**。
4. 在命令行中看到 `成功：演示生成.dbc，共 2 条报文、7 个信号`，即完成文本转换。
5. 可用文本编辑器打开 `.dbc`，观察 `BO_`（报文）和 `SG_`（信号）。将来再用 CANdb++ / 其他兼容工具打开逐项核对。

也可直接用终端运行：

```bash
python excel_to_dbc.py "标准通信矩阵模板.xlsx" "演示生成.dbc"
python test_converter.py
```

在部分 Windows 机器上，Python 命令可能是 `py -3`，则改用 `py -3 excel_to_dbc.py ...`。

## Excel 各列是什么意思？

**Messages（每行一条报文）**：`Name` 报文名、`ID` 例如 `0x180`、`FrameType` 选择 `Standard` / `Extended`、`DLC` 长度（1～8字节）、`Sender` 发送节点、`CycleMs` 周期毫秒。

**Signals（每行一个信号）**：`MessageName` 所属报文、`Name` 信号名、`StartBit` 起始位、`Length` 位长度、`ByteOrder` 仅支持 `Intel`、`Signed` 有符号/无符号、`Factor` 比例系数、`Offset` 偏移量、`Min/Max` 物理量程、`Unit` 单位、`Receiver` 接收节点。

换算公式：**物理值 = 原始值 × Factor + Offset**。

比如演示中的 `VehicleSpeed` 比例系数为 0.01，如果原始值是 1234，则表示 `12.34 km/h`。

## 常见问题

**Q：生成的 DBC 可以直接用于真实项目吗？**

不能。这里只有独立设计的模拟数据，且不覆盖常见复杂 DBC 特性，需要人工审核并做工具兼容性验证。

**Q：为什么提示 Motorola 不支持？**

本期故意限制为 Intel 小端，防止入门时把 `@0` 大端信号错误生成为 `@1` 小端信号。后续再单独讲解大端起始位。

**Q：为什么两个信号不能占相同的 bit？**

当前脚本不支持多路复用信号，对单一路径信号检查重叠，防止写出明显错误的布局。

**Q：需要付费购买额外资料才能运行吗？**

不需要，这个项目的完整基础示例和 8 项测试都在本文件夹里。

## 当前限制与下一步

- **不支持** Motorola、CAN FD、复用信号、J1939 完整属性、复杂接收关系、部分单位编码和 ENUM 描述；
- 对输入 Excel 的物理量程目前只做基本合法性检查，未验证是否与全部原始值范围一致；
- 当前未实际在 CANdb++ 里完成导入检查，也未做真实硬件收发；
- 计划下一期补上软件界面导入验证和报文解读截图（如允许公开）。
